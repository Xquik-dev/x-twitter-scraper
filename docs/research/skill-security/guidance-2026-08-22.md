# Skill security and eval guidance

Reviewed on 2026-08-22.

This record covers the three sources required by the repository goal. It fixes
the source revisions used by the Skill scan and eval gates.

## NVIDIA SkillSpector

- Source: <https://github.com/NVIDIA/SkillSpector>
- Stable release: `v2.9.6`, published 2026-08-18
- Stable tag commit: `29b0dc8c39424e8e31ca055fa027adf8ba8f9650`
- Repository head checked: `698e2bf29c7d32aa8211ada677382460c01900d7`
- Review date: 2026-08-22

The stable scanner runs pattern, Python AST, dependency, OSV, YARA, taint, and
permission checks. Semantic checks need a configured model provider. A scan
never executes the inspected Skill.

The JSON recommendation is the release gate. Exit code 0 can mean `SAFE` or
`CAUTION`, so the gate must read `risk_assessment.recommendation`. It must also
reject scanner errors, degraded semantic coverage, and active findings.

Exact fingerprint suppressions bind the scanner version, Skill text, finding,
and evidence. Source or scanner changes reactivate the finding. Use them only
for reviewed false positives. Keep the reason and expiry in the review record.

## Agent Skills eval guidance

- Source: <https://agentskills.io/skill-creation/evaluating-skills>
- Served revision: `dpl_aPQbxymFRLG4TRcAb4iVkpHpUT94`
- Review date: 2026-08-22

Each Skill keeps realistic cases in `evals/evals.json`. A case has a prompt,
expected output, optional inputs, and objective assertions. Runs compare the
Skill against a no-Skill or previous-version baseline in clean contexts.

Each iteration stores separate outputs, grades, timing, benchmark data, and
human feedback. Mechanical checks grade files, JSON, counts, commands, and
permissions. Human review covers meaning and usefulness. Failed assertions and
specific reviewer comments become later regression cases.

## OpenAI Skill eval guidance

- Source: <https://developers.openai.com/blog/eval-skills>
- Published: 2026-08-22
- Last modified: 2026-08-22 07:34:22 GMT
- ETag: `850031ce02698b4949b7b845f8246272`
- Review date: 2026-08-22

Define outcome, process, style, and efficiency goals before changing a Skill.
Start with 10 to 20 prompts. Cover explicit, implicit, contextual, and negative
activation cases.

Use `codex exec --json` for clean JSONL traces. Grade command order, output
files, token counts, duration, and permission use. Use fixed JSON schemas for
read-only model grading when code cannot judge a requirement. Keep slower
runtime checks only when they catch a measured risk.

## Repository decisions

- Scan each complete Skill directory separately.
- Pin the stable SkillSpector release and tag commit.
- Accept only `SAFE` with zero active findings.
- Run semantic analysis when a configured provider is available.
- Keep raw traces and unsafe interim reports outside tracked files.
- Keep sanitized final JSON scan results with source hashes.
- Block stale results, expired suppressions, failed must-pass evals, and extra
  permissions in CI.
- Do not treat model grading as human review.
