# Scrapfly X scraping guide source review

- Reviewed: 2026-08-22
- Source: [Scrapfly X scraping guide](https://scrapfly.io/blog/posts/how-to-scrape-twitter)
- Source type: Technical guide and vendor comparison

## Audience

Python developers deciding between browser automation and a managed scraper.

## Questions answered

- Why did older free libraries stop working?
- What does a self-managed browser scraper maintain?
- How can code capture profile and tweet data?
- Which data remains unavailable without a login?

## Claims recorded

The guide says browser automation requires tokens, changing query identifiers,
sessions, suitable network access, pacing, and ongoing repairs. Its maintenance,
timing, and blocking figures are vendor claims until independently measured.

## Evidence and examples

The page includes Python examples using Scrapfly's SDK and browser responses. It
shows profile and tweet parsing. It clearly limits anonymous search and follower
access.

## Pricing record

The guide gives no complete matched-workload price. It mentions request counts,
transfer size, and proxy cost ranges. The Scrapfly pricing page must provide
current billing inputs.

## Structure and requested action

The guide compares four operating models before explaining browser mechanics.
It ends with product links, FAQs, and legal cautions.

## Xquik lesson

Compare upkeep, not code length. State what clients do not maintain. Avoid
promising fields or history that the source cannot return.
