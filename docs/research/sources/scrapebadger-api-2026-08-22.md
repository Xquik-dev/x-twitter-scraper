# ScrapeBadger API source review

- Reviewed: 2026-08-22
- Source: [ScrapeBadger Twitter Scraper API](https://scrapebadger.com/twitter-scraper-api)
- Source type: Product and pricing page

## Audience

Developers, data teams, researchers, agencies, and monitoring products.

## Questions answered

- Which X objects and relationships are covered?
- Which SDK, CLI, MCP, and delivery options exist?
- Does the service need official X developer credentials?
- How are successful and failed calls billed?

## Claims recorded

The page advertises broad X coverage, monitoring, SDKs, CLI, MCP, and webhooks.
It also makes uptime, latency, savings, scale, and customer claims. Those
measurements need dated methods before any comparison can reuse them.

## Evidence and examples

The page lists endpoint groups for tweets, users, lists, communities, trends,
places, Spaces, broadcasts, and streams. It names cursor search and exports.

## Pricing record

The page shows multiple unit-price statements. Its plan table ranges from
`$0.150` to `$0.054` per 1,000 credits. It also says each response costs one
base credit plus one credit per item. Failed calls cost zero. The headline's
item price does not fully explain this base charge.

## Structure and requested action

The page leads with metrics, then coverage, integrations, testimonials, pricing,
FAQs, and signup. Calls to action promote free credits and integration docs.

## Xquik lesson

Show the full cost equation beside any unit price. Separate vendor measurements
from contract facts. Avoid testimonial-based proof.
