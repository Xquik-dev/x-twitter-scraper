Xquikは世界最速かつ最安値のX(Twitter)スクレイパーサービスで、最も網羅的なXデータを提供します。XquikのX (Twitter) Monitorは、選んだアカウントとキーワードについてTwitterのアラートを送ります。監視しているアカウントの新しいツイート、返信、引用、リポスト、プロフィールの変更をすべて捕捉します。通常、Xに表示されてから一秒もかからずに、それぞれを捕捉します。キーワードについては、Xの最新の検索結果に表示される新しいツイートをすべて捕捉します。フォローとフォロワーも捕捉します。各イベントは、アラートとしてDiscord、Telegram、Slack、またはWebhookに届きます。他のApify Actorの多くは、フィルタリングや重複排除の前に課金します。Xquikが課金するのは、配信した重複のない結果だけです。このActorでは、モニターが監視した時間だけに課金します。

アカウントかキーワードを貼り付けて、Startをクリックします。監視はすぐに始まり、アラートは実行と実行の間に届きます。料金は**monitor-hourあたり$0.0045**です。イベントとアラートは無料で、Apifyのプラットフォーム利用料は別途かかります。

> Xquikは独立したサードパーティサービスです。X Corpとは提携していません。
> 「Twitter」および「X」はX Corpの商標です。

## Twitterモニターが送る内容

- 監視しているアカウントのすべての新しいツイート、返信、引用、リポスト。通常、Xに表示されてから一秒もかからずに捕捉します。
- キーワードについて、Xの最新の検索結果に表示されるすべての新しいツイート。Xの検索演算子はどれでも使えます。
- 削除されたツイート、アカウントが始めたライブ動画とスペース。
- 表示名、ユーザー名、自己紹介、プロフィール画像、ヘッダー画像、所在地、ウェブサイト、認証、非公開設定、固定ツイート、表示の可否などのプロフィールの変更。これも通常、Xに表示されてから一秒もかからずに捕捉します。
- 監視している各アカウントがフォローまたはフォロー解除したアカウント。
- 監視している各アカウントの新しいフォロワーと失ったフォロワー。`eventTypes` で選びます。
- メンション、ハッシュタグ、メディア、リンク、投票を含むツイートと長文ツイート。`eventTypes` で選びます。
- イベントの全体、つまり著者、各種カウント、メディアを含むツイート、または変更の内容。
- 現在のユーザー名に並ぶ、変わらないXのユーザーID。名前を変えたアカウントもモニターを保ちます。
- SlackとDiscordにはそれぞれのメッセージ形式で、Telegramにも、任意のHTTPS Webhookには署名付きJSONで届くアラート。
- 新しいWebhook、Slack、DiscordのURLごとのテストアラート。応答は実行ステータスに表示されます。Telegramでは、Startを押すとチャットで確認が届きます。
- 実行のデータセットと、保存済みのタスクまたはモニター名ごとに1つの履歴データセットに入るすべてのイベント。

## Twitterのキーワードアラートを設定する方法

1. Apify ConsoleでXquikのX (Twitter) Monitorを開きます。
2. ユーザー名を `twitterHandles` に、またはXの検索を `searchTerms` に貼り付けます。
3. アラートを送るイベントを選びます。新しいツイート、返信、引用、リポストはデフォルトでオンです。
4. WebhookのURLを `webhookUrls` に貼り付けるか、`telegram` をオンにします。
5. Startをクリックします。その実行で監視が始まります。
6. 同じ入力でActorを1時間ごとに実行するスケジュールを追加します。

以降の各実行は、前回の実行から監視した時間を課金します。新しいイベントをデータセットに保存し、すぐに終わります。24時間実行のないモニターは一時停止します。その4時間前に、アラートで警告が届きます。次の実行でモニターが再開し、未払いの時間を先に課金します。

同じ入力は同じモニターを続けます。入力を変えると、それらのモニターが更新されます。保存済みのタスク1つで、モニターのセットを1つ保ちます。タスクがない場合は `monitorName` がそのセットに名前を付けるので、2つの名前で2つのセットを分けられます。

## Discord、Telegram、SlackでTwitterのアラートを受け取る

- **Discord。** チャンネルのWebhook URLを `webhookUrls` に貼り付けます。各アラートはDiscordのメッセージとして届きます。ホストするボットは不要です。
- **Telegram。** `telegram` をオンにします。実行ステータスに、XquikのTelegramボットへのリンクが表示されます。リンクを開いてStartを押すと、そのチャットにアラートが届きます。
- **Slack。** Incoming WebhookのURLを貼り付けます。各アラートはSlackのメッセージとして届きます。
- **任意のアプリ。** HTTPSのURLを貼り付けます。各アラートは署名付きJSONで届きます。データセットにあるものと同じイベントです。

新しいWebhook、Slack、DiscordのURLには、それを追加した実行でテストアラートが届き、届いたかどうかはステータスページに表示されます。Telegramにはテストアラートを送りません。Startを押すとボットがチャットで応答し、次の実行でTelegramが接続済みと表示されます。

## 入力

| フィールド                           | 内容                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------- |
| `twitterHandles`                     | @の有無を問わないユーザー名、またはx.comのプロフィールURL。1行に1つ。                  |
| `searchTerms`                        | `"x api" lang:en` のようなXの検索。検索1つが1モニターです。                            |
| `monitorName`                        | 保存済みのタスクがない実行で、このアカウントとキーワードのセットに名前を付けます。     |
| `newPosts`                           | すべての新しいツイート。デフォルトでオンです。                                         |
| `replies`, `quotes`, `reposts`       | 返信、引用ツイート、リポスト。デフォルトでオンです。                                   |
| `deletedPosts`, `liveVideos`         | アカウントの削除されたツイート、ライブ動画、スペース。                                 |
| `profileChanges`, `followingChanges` | アカウントのプロフィールの変更、フォロー、フォロー解除。                               |
| `eventTypes`                         | チェックボックスの代わりに使う、正確なイベントの種類。フォロワーの変化やメディアなど。 |
| `webhookUrls`                        | HTTPSのURLを1行に1つ。ActorがSlackとDiscordのURLを判別します。                         |
| `telegram`                           | 実行が示すリンクを通じて、Telegramにアラートを送ります。                               |
| `since`                              | 過去30日以内の日付から保管しているイベントを、1回だけ保存します。                      |
| `stop`                               | モニターを止め、アラートをオフにします。                                               |

1つの入力で、アカウントとキーワードを合計100件まで指定できます。キーワードはツイートのイベントだけを送ります。フレーズを引用符で囲むと、`"x api"` のように完全一致で探します。引用符がなければ、単語はツイートのどこに出てきてもかまいません。アカウントへのメンションを捕捉するには、キーワード `@username` を追加します。Telegramにはユーザー名もチャットIDも不要です。実行ステータスにリンクが表示されます。リンクを開いてStartを押すと、そのチャットにアラートが届きます。

次の入力はそのままコピーできます。

```json
{ "twitterHandles": ["NASA", "SpaceX"], "reposts": false }
```

```json
{
  "searchTerms": ["\"your brand\" -from:yourbrand"],
  "webhookUrls": "https://hooks.slack.com/services/T000/B000/XXXX",
  "monitorName": "brand-mentions"
}
```

```json
{ "twitterHandles": ["elonmusk"], "profileChanges": true, "telegram": true }
```

## 出力

各実行は4つの出力を返します。

- **ステータスページ**、つまり `STATUS.html` レコード。モニターが監視中かどうか、ボタン付きの次の手順1つ、実行が保存して課金した内容、対象、各送信先を表示します。Outputタブに表示されます。
- **ステータスレコード**、つまり `STATUS` レコード。同じステータスをJSONで保持します。
- **新しいイベント**、つまり実行のデータセット。新しいイベントが古い順に並び、最後に1行のステータス行が入ります。
- **診断**。対応が必要なことがあるときだけ書き込みます。

イベント行は、XquikのREST APIが返すイベントそのもので、すべてのフィールドを含みます。

```json
{
  "resultType": "event",
  "id": "981",
  "type": "tweet.new",
  "occurredAt": "2026-10-13T09:00:01.000Z",
  "monitorId": "2944",
  "monitorType": "account",
  "username": "NASA",
  "xUserId": "11348282",
  "data": { "tweetId": "1977000000000000000", "text": "Liftoff!" }
}
```

サンプル値は形を示すものです。ライブデータは異なります。

ステータスレコードには `state`、`targets`、`destinations`、`eventsSaved`、`pendingEvents`、`hoursCharged`、`chargedUsd`、`chargeConfirmed`、`hoursOwed`、`paidThrough`、`pausesAt`、`historyDataset`、`notices`、`nextStep`、`nextStepAction`、`nextStepUrl` が入ります。Xに存在しない対象は、その `message` でそう伝え、モニターは残りを監視します。新しい汎用Webhookは、署名シークレットを1回だけ、ステータスレコードにだけ表示します。

アカウント内の履歴データセットは、モニターのすべてのイベントを1回ずつ保存します。名前は `x-monitor-` で始まります。

## AIエージェント向け

API全体が1回の呼び出しです。各呼び出しはモニターを開始または更新し、前回の呼び出しから監視した時間を課金し、新しいものだけを返します。同じ時間を2回課金する呼び出しはありません。モニターを開始または更新する呼び出しはすぐに終わり、ApifyのMCPが待つ時間内に収まります。停止は最後のイベントを先に集めるため、少し時間がかかります。ツールが待つのをやめたら、実行から結果を読み取ってください。

次の入力でモニターを開始または継続します。

```json
{
  "twitterHandles": ["NASA"],
  "searchTerms": ["\"x api\" lang:en"],
  "monitorName": "agent-demo"
}
```

呼び出しは2つのものを返します。

- 実行のデータセットには、新しいイベントのあとに、`resultType` が `status` の行が1行入ります。その `state` はモニターが監視中かどうかを、`nextStep` は次にすることを示します。`nextStepAction` は `add_schedule` のような手順の種類を示し、`nextStepUrl` はその手順のページです。
- `STATUS` レコードには同じステータスが入ります。呼び出しでWebhookを作成した場合は、署名シークレットも入ります。

モニターを確認するには、同じ入力でActorをもう一度呼び出します。何も変わらず、課金はすでに監視した時間だけです。ステータスと新しいイベントを返します。

モニターが監視を続けるには、少なくとも24時間に1回の実行が必要です。ApifyのMCPサーバーにはスケジュールのツールがないので、スケジュールは自分では追加できません。`nextStepUrl` のページでApifyのスケジュールを追加するよう、ユーザーに頼んでください。そのスケジュールが、同じ入力でActorを1時間ごとに実行します。または、任意のタイマーから自分でActorをもう一度呼び出します。止めるには、同じ入力に `"stop": true` を付けて実行します。

Actorは、`handles` や `usernames` のようにエージェントが推測しがちな名前も読み取ります。どう読み取ったかは実行ステータスに表示されます。

## Twitterモニターの費用は？

すべてのApify有料プランで、monitor-hourあたり$0.0045です。アカウントまたはキーワード1つが1モニターです。アカウント2つとキーワード1つの入力は、1時間ごとに3 monitor-hourかかります。Apifyのプラットフォーム利用料は別途かかります。

- 1アカウントを30日間監視すると、約$3.24です。
- 10アカウントと2キーワードを30日間監視すると、約$38.88です。
- イベントとアラートは、いくつ届いても無料です。
- 開始料金はかかりません。実行が課金するのは、すでに監視した時間だけです。
- Xに存在しない対象は何も監視せず、費用もかかりません。
- 実行あたりの最大コストが、各課金に上限をかけます。上限を超えた時間は次の実行まで待ちます。

1時間ごとのスケジュールなら、支払う監視時間に比べてApifyの利用料は小さく済みます。数分ごとの実行は利用料を増やすだけで、アラートには何の違いもありません。アラートはどのみち実行と実行の間に届きます。

監視にはApifyの有料プランが必要です。無料プランでは、実行はモニターを開始せず、課金もしません。代わりに最初のアカウントの最新ツイート5件を表示するので、アラートに入る内容を確認できます。

## 制限と復旧

- 1つの入力で、アカウントとキーワードを合計100件まで指定できます。それ以上は2つのタスクを使ってください。
- Webhook URLは1つの入力あたり10件までで、ほかにTelegramも使えます。
- イベントは30日間保管されるので、その期間内なら `since` で再び保存できます。
- 早く止まった実行は、そのイベントを次の実行に残します。失われるイベントはありません。
- 時間の予約から課金までの間に終わった実行は、何も課金しません。その時間は支払い済みとして扱われ、無料になります。
- 各実行は無料のステータス行を1行書き込むので、データセットが空になることはありません。

## よくある質問

よくある質問に答えたあと、サポートを受けられる場所を案内します。

### XのCookie、APIキー、ログインは必要ですか？

いいえ。XquikのX (Twitter) Monitorは、XのCookie、APIキー、ログイン、認証情報を必要としません。チェックはすべてXquikのインフラで実行します。

### Twitterアカウントを監視するにはどうすればいいですか？

ユーザー名を `twitterHandles` に貼り付け、必要なイベントを選んで、アラートの送信先を追加します。Xquikは通常、新しいツイートをXに表示されてから一秒もかからずに捕捉し、すべてのイベントはデータセットに残ります。

### 暗号資産のアカウントやコインへの言及も監視できますか？

はい。フォローしているアカウントを追加するか、キャッシュタグやコントラクトアドレスなどのキーワード検索を追加します。それらのアカウントの新しいツイートと一致したツイートが、アラートとしてDiscordやTelegramに届きます。

### アラートはどのくらい速く届きますか？

Xquikは通常、監視しているアカウントの新しいツイート、返信、引用、リポスト、プロフィールの変更を、Xに表示されてから一秒もかからずに捕捉します。アラートはイベントが届くたびに送られ、実行を待つことはありません。

### 監視に有料プランが必要だと実行に表示されるのはなぜですか？

モニターは実行と実行の間も、1日中動きます。そのため、Apifyの有料プランが必要です。アップグレードしてから、同じ入力でもう一度実行してください。

### モニターを止めるとどうなりますか？

実行はすべての対象を止め、アラートをオフにします。それまでに監視した時間を課金します。その後、最新のイベントを少し待って保存するので、取り残されるイベントはありません。すでに保管されたイベントは、30日間読み取れます。

### Webhookの署名はどう確認しますか？

新しい汎用Webhookには署名シークレットが発行され、`STATUS` レコードに1回だけ表示されます。Xquikはこのシークレットで各配信に署名します。XquikのREST Webhookと同じ方法です。

### API、スケジュール、連携は使えますか？

はい。Apify APIまたはXquik REST APIを使ってください。[APIタブ](https://apify.com/xquik/x-twitter-monitor/api)には、Python、JavaScript、cURLの例があります。Apifyの[スケジュール](https://docs.apify.com/platform/schedules)で、モニターを動かし続けられます。エージェントは[Apify MCP](https://docs.apify.com/platform/integrations/mcp)から呼び出せます。

### Xアカウントを監視しても合法ですか？

XquikのX (Twitter) Monitorは、Xの公開データを取得します。結果には個人データが含まれることがあります。目的が合法であることを確認し、自分に適用されるプライバシー規則に従ってください。判断に迷う場合は、資格のある弁護士に相談してください。

### どこでサポートを受けられますか？

Actorページでissueを開くか、実行IDを添えて<support@xquik.com>に連絡してください。ステータスページがすべての実行を説明し、対応が必要な実行は無料の診断情報がカバーします。

### カスタムソリューションを依頼できますか？

はい。[xquik.com](https://xquik.com)にアクセスするか、[APIドキュメント](https://docs.xquik.com/introduction)をお読みください。ダッシュボード、API、MCPサーバー、Webhookについて説明しています。
