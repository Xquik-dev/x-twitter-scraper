Xquikは世界最速かつ最安値のX(Twitter)スクレイパーサービスで、最も網羅的なXデータを提供します。XquikのX (Twitter) Follower Trackerは、選んだアカウントの新しいフォロワーと失ったフォロワー、そのアカウントが誰をフォローまたはフォロー解除したかを表示します。各アラートには相手のアカウントの全プロフィールが入ります。他のApify Actorの多くは、フィルタリングや重複排除の前に課金します。Xquikが課金するのは、配信した重複のない結果だけです。このActorでは、モニターが監視した時間だけに課金します。

追跡するアカウントを貼り付けて、Startをクリックします。アラートは実行と実行の間に届きます。料金は**monitor-hourあたり$0.0045**です。イベントとアラートは無料で、Apifyのプラットフォーム利用料は別途かかります。

> Xquikは独立したサードパーティサービスです。X Corpとは提携していません。
> 「Twitter」および「X」はX Corpの商標です。

## X (Twitter) Follower Trackerを使う理由

- **誰がフォローを外したかがわかる。** 失ったフォロワーのアラートは、Xが凍結したアカウントでも、そのアカウントを示します。
- **どの公開アカウントも追跡できる。** 自分のアカウント、競合のアカウント、クライアントのアカウントを監視できます。
- **既存のフォロワーにはアラートなし。** 最初の実行は、各リストをそのまま記録します。アラートが届くのは、その後の変化だけです。
- **チャットアプリにアラート。** Telegram、Discord、Slackに送れます。TelegramにはチャットIDが要りません。任意のHTTPS Webhookにも、イベントの全体が届きます。
- **アラートが届くか確認できる。** 新しいWebhook、Slack、DiscordのURLごとにテストアラートが届きます。届いたかどうかは実行ステータスに表示されます。
- **モニターが監視中だとわかる。** 各実行のステータスページがそれを示し、次の手順を1つ、ボタン付きで表示します。
- **知らないうちに止まらない。** 実行のないモニターが一時停止する4時間前に、アラートで警告します。次の実行で再開します。
- **Xのアカウントは不要。** Xのログイン情報やAPIキーを共有することはありません。

### 正確な行

- 行の中のIDはすべて正確なままです。
- 認証バッジは `x.com` の表示と一致します。
- 行には公開データだけが入ります。
- 広告&プロモーションの項目が行に入ることはありません。
- モニターが報告するのは、実際の削除&フォロー解除だけです。

### 最新のデータ

- Xが変更を加えても、読み取りは動き続けます。

### 速度

- 遅いページが1つあっても、実行は止まりません。
- 止まったActorの呼び出しは、自動で回復します。

### 公正な課金

- モニターの料金は1時間あたりの定額で、イベント&Webhookも含みます。
- モニターのActorは、モニターが監視した時間だけに課金します。

### 信頼性

- 一度きりのエラーで実行が失敗することはありません。
- Xquikの短い障害があっても、Actorは動き続けます。
- Actorの実行は、再起動しても重複なく続きます。
- 停止した実行にも、行&レポートが残ります。
- 開始できない実行も、その理由を説明します。
- Webhookは署名付きで、リプレイ攻撃にも安全です。
- 停止していたWebhookにも、最大7日間はイベントが届きます。
- Webhookが停止した後でも、新しいイベントは時間どおりに届きます。
- Webhookがプライベートなホストやローカルのホストに送られることはありません。
- チャットのアラートは、レート制限にかからずに順番どおり届きます。
- サポートは、リクエストや実行が返した内容を正確に確認できます。

### エージェント向けの設計

- Actorは、他のActor向けに書かれた入力も受け付けます。
- どの実行も、終了した理由&再試行すべきかどうかを示します。

### 品質チェック

- Xが表示するフィールドはすべて、提供されるか、意図的に除かれるか、存在しないことが確認されています。
- Xquikは、すべての読み取りを実際のXでテストしています。
- ActorのREADME、スキーマ&実際の出力は、同じフィールド名を使います。

## X (Twitter) Follower Trackerが送るデータ

- 新しいフォロワー。監視している各アカウントをフォローし始めたアカウントです。
- 失ったフォロワー。そのアカウントのフォロワーから外れたアカウントです。
- 新しいフォローとフォロー解除。そのアカウントがフォローし始めた、またはフォローをやめたアカウントです。
- 各アラートには、名前、自己紹介、フォロワー数など、相手のアカウントの全プロフィールが入ります。
- 実行のデータセットと1つの履歴データセットに入るすべてのイベント。

## Twitterのフォロワーを追跡する方法

監視にはApifyの有料プランが必要です。[プランを選び](https://apify.com/pricing?fpr=xquik)、ここに戻ってTry for freeを押してください。

1. Apify ConsoleでXquikのX (Twitter) Follower Trackerを開きます。
2. ユーザー名を `twitterHandles` に貼り付けます。
3. `telegram` をオンにするか、DiscordかSlackのWebhook URLを `webhookUrls` に貼り付けます。
4. Startをクリックします。その実行で追跡が始まります。
5. 同じ入力でActorを1時間ごとに実行するスケジュールを追加します。

以降の各実行は、前回の実行から監視した時間を課金し、新しいイベントをデータセットに保存します。24時間実行のないモニターは一時停止します。その4時間前に、アラートで警告が届きます。次の実行でモニターが再開し、未払いの時間を先に課金します。

## トラッカーが見るもの

- 任意の公開アカウントの新しいフォロワーと新しいフォロー。
- フォロワーが100,000人までのアカウントの失ったフォロワーと、フォローが100,000件までのアカウントのフォロー解除。それを超える場合は、最新の5,000件の中から見ます。
- 大きなリストの奥にいる失ったフォロワーは、新しいフォロワーより遅れて届くことがあります。Xquikはリスト全体を、最新のフォロワーより低い頻度で確認するためです。
- アカウントがXに凍結または削除されたフォロワーも、失ったフォロワーとして数えます。
- いったん外れて戻ってきたアカウントは、もう一度新しいフォロワーとして数えることがあります。
- 最初の実行は各リストをそのまま記録するので、既存のフォロワーは新しいフォロワーとして数えません。
- 非公開アカウントはリストを隠すので、何も送りません。

## 入力

| フィールド | 内容 |
| --- | --- |
| `twitterHandles` | @の有無を問わないユーザー名、または `x.com` のプロフィールURL。1行に1つ。 |
| `monitorName` | 保存済みのタスクがない実行で、このアカウントのセットに名前を付けます。 |
| `followerChanges` | 新しいフォロワーと失ったフォロワー。デフォルトでオンです。 |
| `followingChanges` | 新しいフォローとフォロー解除。デフォルトでオンです。 |
| `webhookUrls` | HTTPSのURLを1行に1つ。ActorがSlackとDiscordのURLを判別します。 |
| `telegram` | 実行が示すリンクを通じて、Telegramにアラートを送ります。 |
| `stop` | モニターを止め、アラートをオフにします。 |

1つの入力で、アカウントを100件まで指定できます。Telegramにはユーザー名もチャットIDも不要です。実行ステータスにリンクが表示されます。リンクを開いてStartを押すと、そのチャットにアラートが届きます。フォームではX (Twitter) Monitorのツイートイベントを隠していますが、それを送る入力もそのまま動きます。

次の入力はそのままコピーできます。

```json
{ "twitterHandles": ["xquikcom"], "telegram": true }
```

```json
{
  "twitterHandles": ["yourhandle"],
  "followingChanges": false,
  "webhookUrls": "https://hooks.slack.com/services/T000/B000/XXXX"
}
```

## 出力

各実行は4つの出力を返します。

- **ステータスページ**、つまり `STATUS.html` レコード。モニターが監視中かどうか、ボタン付きの次の手順1つ、実行が保存して課金した内容、対象、各送信先を表示します。Outputタブに表示されます。
- **ステータスレコード**、つまり `STATUS` レコード。同じステータスをJSONで保持します。
- **新しいイベント**、つまり実行のデータセット。新しいイベントが古い順に並び、最後に1行のステータス行が入ります。
- **診断**。対応が必要なことがあるときだけ書き込みます。

イベント行は、XquikのREST APIが返すイベントそのもので、すべてのフィールドを含みます。ステータスレコードには、X (Twitter) Follower Trackerが表示するとおりに `state`、`targets`、`destinations`、`eventsSaved`、`hoursCharged`、`paidThrough`、`pausesAt`、`nextStep`、`nextStepAction`、`nextStepUrl` が入ります。

アカウント内の履歴データセットは、モニターのすべてのイベントを1回ずつ保存します。名前は `x-monitor-` で始まります。

## AIエージェント向け

API全体が1回の呼び出しです。各呼び出しはモニターを開始または更新し、前回の呼び出しから監視した時間を課金し、新しいものだけを返します。同じ時間を2回課金する呼び出しはありません。モニターを開始または更新する呼び出しはすぐに終わり、ApifyのMCPが待つ時間内に収まります。停止は最後のイベントを先に集めるため、少し時間がかかります。

次の入力でモニターを開始または継続します。

```json
{ "twitterHandles": ["xquikcom"], "monitorName": "agent-demo" }
```

実行のデータセットには、新しいイベントのあとに、`resultType` が `status` の行が1行入ります。その `state` はモニターが監視中かどうかを、`nextStep` は次にすることを示します。モニターを確認するには、同じ入力でActorをもう一度呼び出します。何も変わらず、課金はすでに監視した時間だけです。

モニターが監視を続けるには、少なくとも24時間に1回の実行が必要です。ApifyのMCPサーバーにはスケジュールのツールがないので、スケジュールは自分では追加できません。`nextStepUrl` のページでApifyのスケジュールを追加するよう、ユーザーに頼んでください。そのスケジュールが、同じ入力でActorを1時間ごとに実行します。止めるには、同じ入力に `"stop": true` を付けて実行します。

## Twitterフォロワートラッカーの費用は？

すべてのApify有料プランで、monitor-hourあたり$0.0045です。アカウント1つが1モニターです。Apifyのプラットフォーム利用料は別途かかります。

- 1アカウントを30日間追跡すると、約$3.24です。
- 10アカウントを30日間追跡すると、約$32.40です。
- イベントとアラートは、いくつ届いても無料です。
- 開始料金はかかりません。実行が課金するのは、すでに監視した時間だけです。
- Xに存在しない対象は何も監視せず、費用もかかりません。
- 実行あたりの最大コストが、各課金に上限をかけます。上限を超えた時間は次の実行まで待ちます。

1時間ごとのスケジュールなら、支払う監視時間に比べてApifyの利用料は小さく済みます。数分ごとの実行は利用料を増やすだけで、アラートには何の違いもありません。アラートはどのみち実行と実行の間に届きます。

監視には[Apifyの有料プラン](https://apify.com/pricing?fpr=xquik)が必要です。無料プランでは、実行はモニターを開始せず、課金もしません。代わりに最初のアカウントの最新ツイート5件を表示します。

## 制限&復旧

- 1つの入力で、アカウントを100件まで指定できます。それ以上は2つのタスクを使ってください。
- Webhook URLは1つの入力あたり10件までで、ほかにTelegramも使えます。
- イベントは30日間保管されるので、その期間内なら `since` で再び保存できます。
- 早く止まった実行は、そのイベントを次の実行に残します。失われるイベントはありません。
- 各実行は無料のステータス行を1行書き込むので、データセットが空になることはありません。
- Xquikの監視Actorはどれも、1時間あたりの料金が同じです。実行は、どのActorが監視したかにかかわらず、すべてのモニターの最も古い未払いの時間を支払います。

## よくある質問

よくある質問に答えたあと、サポートを受けられる場所を案内します。

### XのCookie、APIキー、ログインは必要ですか？

いいえ。XquikのX (Twitter) Follower Trackerは、XのCookie、APIキー、ログイン、認証情報を必要としません。チェックはすべてXquikのインフラで実行します。

### Xで自分のフォロワーから外れた人を確認できますか？

はい。自分の公開アカウントを監視します。フォロワーから外れた各アカウントについて、全プロフィール付きの失ったフォロワーのアラートが届きます。フォロー解除したアカウントと、Xが凍結または削除したアカウントも含みます。

### アカウントが誰をフォローしているかわかりますか？

はい。`followingChanges` はデフォルトでオンなので、監視しているアカウントがフォローし始めた、またはフォローをやめたアカウントごとにアラートが届きます。

### フォロワーが数百万人のアカウントでも使えますか？

任意の公開アカウントの新しいフォロワーを示します。失ったフォロワーは、フォロワーが100,000人までのアカウントで示します。それを超える場合は、最新の5,000件の中から示します。

### ツイートも送りますか？

デフォルトでは送りません。`eventTypes` でツイートのイベントをオンにするか、ツイートにはX (Twitter) Monitorを使ってください。

### 監視に有料プランが必要だと実行に表示されるのはなぜですか？

モニターは実行と実行の間も、1日中動きます。そのため、Apifyの有料プランが必要です。アップグレードしてから、同じ入力でもう一度実行してください。

### モニターを止めるとどうなりますか？

実行はすべての対象を止め、アラートをオフにします。それまでに監視した時間を課金します。その後、最新のイベントを少し待って保存するので、取り残されるイベントはありません。すでに保管されたイベントは、30日間読み取れます。

### API、スケジュール&連携は使えますか？

はい。Apify APIまたはXquik REST APIを使ってください。[APIタブ](https://apify.com/xquik/x-twitter-follower-tracker/api)には、Python、JavaScript、cURLの例があります。Apifyの[スケジュール](https://docs.apify.com/platform/schedules)で、モニターを動かし続けられます。エージェントは[Apify MCP](https://docs.apify.com/platform/integrations/mcp)から呼び出せます。

### Xアカウントを監視しても合法ですか？

XquikのX (Twitter) Follower Trackerは、Xの公開データを取得します。結果には個人データが含まれることがあります。目的が合法であることを確認し、自分に適用されるプライバシー規則に従ってください。判断に迷う場合は、資格のある弁護士に相談してください。

### どこでサポートを受けられますか？

実行IDを添えて[Issuesタブ](https://apify.com/xquik/x-twitter-follower-tracker/issues)でissueを開いてください。ステータスページがすべての実行を説明し、対応が必要な実行は無料の診断情報がカバーします。

### カスタムソリューションを依頼できますか？

はい。必要な内容を[Issuesタブ](https://apify.com/xquik/x-twitter-follower-tracker/issues)に書いてください。Xquikはダッシュボード、REST API、MCPサーバー、Webhookも提供しています。Xquikのウェブサイトは[Apifyのプロフィール](https://apify.com/xquik)にあります。
